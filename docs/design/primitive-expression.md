# Local expressions and algebraic evaluation

Updated: 2026-11-04

## 1. Scope and responsibilities

This document defines core's `LocalState<S,O,C>` and `LocalOperator<O,C>` and the extension of primitive capabilities to expressions. See [local algebras](local-structure.md) for concrete primitives/normalization, [construction](expression-construction.md) for type selection/inputs, and [numerics](numerics.md) for coefficient capabilities.

Local Product/Act/adjoint rules return finite primitive combinations; shared expressions provide delayed syntax and evaluation. Local expressions have no index. See [composite expressions](composite-expression.md) for placement and full-space evaluation.

## 2. Primitive capabilities

State primitives span the full state space and operator primitives the full operator space. Primitives need not be independent and differ from a selected basis.

| Implemented by | Capability | Input | Result |
| --- | --- | --- | --- |
| State primitive | Inner product | Two states | Complex scalar. |
| Operator primitive | Product | Two operators | Finite operator combination. |
| State primitive | Act | State and operator | Finite state combination. |
| Operator primitive | Adjoint | Operator | Finite operator combination. |
| Operator primitive | Trace | Operator | Complex scalar. |
| State/operator primitive | Parity for grading | Primitive | Even/odd. |

Product belongs to operator primitives, Act to states for a particular state/operator type pair. `state.act(&operator)` means operator*state. Corresponding types and representation parameters obey the local algebra contract.

State expressions specify S/O/C and operators O/C. Identity is generated by O: Identity, dimensions by S/O: Dimension. Evaluation methods require the needed capabilities/type relationships; storage does not require all operations or a LocalStructure/definition label.

Product/Act/adjoint return thin LinearCombination values of primitives of the same local structure, not necessarily one primitive. Traits take whole C and associated Term without depending on local expression/structure objects. Local Term is the corresponding primitive, mapped into sum/scale syntax by expressions. O: Identity produces a primitive value and Basis expands it if needed. Local rules return evaluated finite combinations rather than delayed local products/actions/adjoints. Shared processing provides addition, scaling, and zero.

Trace is the ordinary unnormalized local Hilbert-space trace. Although derivable from an orthonormal basis, action, and inner product, the usual path directly uses primitive trace without expansion or numerical matrices.

Graded primitives are homogeneous; mixed parity is a sum. Local algebras provide a parity operator and consistency among graded capabilities.

## 3. Shared construction and evaluation

| Target | Operation | Evaluation responsibility |
| --- | --- | --- |
| State | Addition, scaling, zero | Linear combinations. |
| State | Inner product | Sesquilinear extension of primitive inner products. |
| Operator | Addition, scaling, zero | Linear combinations. |
| Operator | Product | Bilinearity/order and primitive Product when needed. |
| State | Operator action | Delayed act, linearity in both inputs, and primitive Act. |
| Operator | Adjoint | Coefficient conjugation, reversed product order, primitive adjoints. |
| Operator | Trace | Linearity and primitive traces. |

For local operators A/B/C, state ψ, and same-precision complex a/b, the shared rules are:

```math
\left\langle\sum_i a_i s_i,\sum_j b_j t_j\right\rangle
=\sum_{i,j}\overline{a_i}b_j\langle s_i,t_j\rangle,
\qquad
(aA+bB)\psi=a(A\psi)+b(B\psi).
```

```math
(aA+bB)C=a(AC)+b(BC),\qquad
A(aB+bC)=a(AB)+b(AC),
\qquad
(AB)\psi=A(B\psi).
```

```math
(aA+bB)^\dagger=\overline a A^\dagger+\overline b B^\dagger,
\qquad
(AB)^\dagger=B^\dagger A^\dagger,
\qquad
\operatorname{Tr}(aA+bB)=a\operatorname{Tr}(A)+b\operatorname{Tr}(B).
```

Inner products are conjugate-linear in the first input and linear in the second. Products/actions are linear in both inputs, adjoints conjugate-linear, traces linear. AB acts from the right: B first, then A.

These laws do not require eager expansion during construction. Retain products/actions/adjoints until inner products, traces, action results, or basis expansion/coordinates require the relevant parts; primitive rules run then.

state.act builds an Act node; state.evaluate resolves pending actions to ordinary state syntax using local Act. `ψ.act(&b).act(&a)` means A(Bψ). Evaluate takes no basis and performs no coordinate or matrix conversion.

Local evaluation and explicit basis expansion/coordinates exist; selecting individual simplification rules does not. Distribution, local products, and coefficient combination remain internal steps when needed.

`LocalOperator::collect_terms()` explicitly evaluates products/adjoints and
combines equal natural primitives using PartialEq. It shares primitive handles,
needs no primitive Clone or Dimension, and removes exact zeros only. Unlike
complete basis expansion, it does not resolve linear relations between distinct
natural primitives. Ordinary construction and evaluation retain their existing
duplicate/zero behavior. Lie residual calculations use this explicit operation
to reduce cancellation before normalized HS contraction.

Common ScaleExpr/SumExpr/ProductExpr/ActExpr/AdjointExpr store node contents. Zero is an empty sum. LinearCombination<P,C> stores `SumExpr<ScaleExpr<P,C>>`. Owned map/common constructors move rule/basis outputs into expressions, preserving coefficients, order, duplicates, and zero coefficients without Clone on elements or coefficients for that conversion.

expr::parts publicly exposes those parts and their contents; root re-exports expression handles. Node enums/shared internals stay private. Term<P,C> aliases ScaleExpr<P,C> with field operand. Linear-combination construction/traversal uses SumExpr. Associated Term in operation traits instead denotes an element without its coefficient.

Evaluators separate state evaluation, operator application, and operator-term traversal. State action needs no primitive Product; trace and other local multiplication paths do. Storage, delayed construction, and map without arithmetic gain no numeric bounds; methods request individual capabilities rather than one combined coefficient trait. Binary operators accept all four owned/borrowed combinations, moving owned handles and cloning shared handles. Named methods primarily borrow.

Evaluation and final-owner node destruction use explicit work stacks, avoiding depth-proportional recursion. Verify long product/action chains and surviving shared subtrees. Performance criteria cover sharing, avoiding unnecessary primitive clones, and allocation-free empty/single-term containers, not allocation-free map in general or guaranteed execution times.

Arc shares immutable nodes and their primitives, so repeated handles do not clone whole trees/primitives. Independently constructed equal-shaped expressions are not automatically merged. Inputs stay unchanged; no common fully expanded representation or evaluation cache is required. Source retention/structural comparison are unavailable. [Formatting](expression-formatting.md) has independent Display/Debug bounds and concrete algebras need no separate expression trees.

## 4. Derived operations

| Target | Operation | Derivation |
| --- | --- | --- |
| State | Norm | `sqrt(⟨ψ,ψ⟩)` from inner products. |
| State | Normalization | Norm and scaling; reject zero norm. |
| Operator | Commutator / anticommutator | `AB−BA` / `AB+BA`. |
| Operator | Hilbert–Schmidt inner product | `Tr(A†B)/d`, with d=Tr(I) and Divide; ordinary trace stays unnormalized. |
| State/operator | Expectation | `⟨ψ,Aψ⟩` from action/inner product. |
| State/operator | Normalized expectation | Divide by self-inner-product; reject zero norm. |

Brakets use inner products. See [normalization](normalization.md) for norm/normalization/normalized-expectation APIs and errors. Local identity is `Primitive(O::identity())` on the ordinary evaluation/expansion path; composite syntax also has OpNode::Identity.

### 4.1. Dimension-normalized Hilbert–Schmidt inner products

Use state-space dimension d locally and full ambient dimension D for composites, not operator-space d² or variant counts:

```math
\langle A,B\rangle_D=\frac{\operatorname{Tr}(A^\dagger B)}{D},\qquad
\|A\|_D^2=\frac{\operatorname{Tr}(A^\dagger A)}{D}.
```

Then `||I||_D=1`, and identity spectators preserve inner products. For Hermitian A this is the second moment `Tr((I/D)A²)` in the maximally mixed state; adding interaction terms does not preserve the norm automatically.

```math
\langle A\otimes I_m,B\otimes I_m\rangle_{Dm}
=\langle A,B\rangle_D.
```

Trace remains ordinary and unnormalized, with Tr(I)=D. Expectations, purity traces, state inner products/norms, and state normalization keep their meanings. Custom algebras/bases need not be orthonormal.

LocalOperator::hs_inner_product divides by O::identity().trace(). Normalize each evaluated primitive trace before multiplying coefficients and summing. Composite hs_inner_product/hs_inner_product_in use the same [ordinary local-trace traversal](composite-expression.md#114-intrinsic-terms-and-ordinary-representations) before contraction. Scaling before or after placement avoids unnecessary unnormalized intermediates. Each local dimension must be a nonzero C supporting mathematical division through Divide; ordinary trace/trace_in gain no division requirement.

This needs no state type, Dimension, integer total dimension, or integer-to-C conversion. Empty spaces have D=1. It avoids usize overflow and growth from multiplying spectator dimensions, without guaranteeing freedom from arbitrary coefficient overflow/rounding. See [trace.rs](../../crates/syntaqs-core/src/evaluate/trace.rs) and [HS regression tests](../../tests/tests/core_hs_inner_product.rs).

## 5. Linear dependence and basis connections

Dependent primitives permit multiple expressions for one object, such as Sp and `(Sx+iSy)/2`. Capabilities preserve those linear relations and give mathematically equal results for equivalent inputs; identical coefficient lists/tree structures are not required.

Evaluation needs no primitive/tree structural comparison. Expansion aggregates by basis index while maintaining local-algebra/index checks independently of structural comparison support.

Exact expansion/coordinates explicitly organize expressions and connect them to bases, preserving linear relations and aggregating members. Primitives do not fix a selected basis, and ordinary actions/inner products/traces need no expansion. Approximate comparison and action equivalence follow [numerics](numerics.md).

A basis struct implements Basis<P,C> with primitive expansion, indices, and ordered enumeration. State/operator outputs are LinearCombination<S,C>/LinearCombination<O,C>, restricted to selected primitive members and mapped into ordinary syntax. Members form a primitive subset; size derives from local structure and target kind, and core extends expansion linearly. See [bases](basis.md).

The basis is an input; the result is ordinary syntax without basis identity or special expanded status. Preserve inputs/local structure and permit ordinary operations and re-expansion without an independent tree basis-change mechanism.

## 6. Consistency verification

Local implementations verify Product associativity, action/product consistency, identity, inner-product/adjoint compatibility, ordinary trace, and primitive linear relations under [local-algebra contracts](local-structure.md). Expressions verify linear/sesquilinear/conjugate-linear extensions, right-first action, adjoint order reversal, and lazy evaluation.

Equalities are mathematical, not bitwise floating-point guarantees; use [numeric conventions](numerics.md).

Separate storage/construction from evaluation capabilities. Verify finite-combination storage, map and conversion, non-Clone primitive sharing, and iterative evaluation/destruction. Follow [primitive type contracts](local-structure.md#4-conditions-for-matching-local-structures) for local-algebra correspondence.
