# 式木表示のカスタムフォーマット検討メモ（一時）

作成日: 2026-11-01

**状態: 現行ソースの調査に基づく推奨案。未実装・未確定。**
本書は [v3 計画](README.md#式木表示のカスタムフォーマット)を具体化するための一時ドキュメントである。表示機能を実装した段階で、採用した契約を設計文書・rustdoc・examples に移し、本書を整理する。

## 1. 推奨する方向

次の3つに責任を分ける。

| 入口 | 用途 | 推奨する表示 |
| --- | --- | --- |
| `println!("{expr}")` / `format!("{expr}")` | 式を読む | 保持している式を数式風の1行に表示する `Display` |
| `{:?}` / `{:#?}` | 構造を調べる | 節点・子の順序・配置・空間を表示する `Debug`。後者はインデント付き |
| 借用する表示用ラッパー | 用途に応じたラベル変更 | Index、primitive、係数の出力方法を明示的に差し替える |

`Display` と `Debug` は局所・複合の4式型に条件付きで実装する。表示のための評価・展開・簡約は行わず、表示能力を式型や構築・評価の共通制約へ追加しない。数式風表示に空間の全情報を詰め込まず、空間の確認には `Debug` を使う。

標準の `Display`・`Debug` と builtin primitive のラベルに加え、**テンソル因子の順序で Index を番号化する表示用ラッパー**を初回に含めることを推奨する。任意のラベルを指定する callback は追加段階とする。標準表示だけでも `println!`・`format!` の利用は成立させる。

## 2. 現行実装で確認できたこと

### 2.1. 表示実装と公開範囲

- `LocalState`・`LocalOperator`・`State`・`Operator` と `HilbertSpace` に `Display`・`Debug` は実装されていない。
- `ScaleExpr`・`SumExpr`・`ProductExpr`・`ActExpr`・`AdjointExpr` と `LinearCombination` には derive による `Debug` がある。ただし、子が式ハンドルの場合は、そのハンドルに `Debug` がないため式全体の表示には使えない。
- spin-half・spin-one・fermion の状態／演算子 primitive には derive による `Debug` があり、`Display` はない。`qmb-basic::Id128` は `Debug` と UUID に委譲する `Display` を持つ。
- 式の節点 enum は非公開で、外部から構造を走査する公開 API はない。任意の外部 crate だけで完全な式表示を実装する構成にはできない。
- `qmb-core` は `no_std + alloc`・unsafe 禁止である。表示も `core::fmt` と必要な `alloc` の範囲に収められる。

参照: [局所式](../../../crates/qmb-core/src/expr/local.rs)、[複合式](../../../crates/qmb-core/src/expr/composite.rs)、[公開パーツ](../../../crates/qmb-core/src/expr/parts.rs)、[線型結合](../../../crates/qmb-core/src/expr/parts/linear_combination.rs)、[core の設定](../../../crates/qmb-core/src/lib.rs)、[Id128](../../../crates/qmb-basic/src/lib.rs)。

### 2.2. 保持している節点

以下は内部表現の調査結果であり、新しい公開 enum の提案ではない。

| 対象 | 節点 | 表示上の注意 |
| --- | --- | --- |
| 局所状態 | `Primitive`・`Scale`・`Sum`・`Act` | 作用節点から局所演算子へ移る |
| 局所演算子 | `Primitive`・`Scale`・`Sum`・`Product`・`Adjoint` | identity は専用節点ではなく `O::identity()` の primitive |
| 複合状態 | `Local`・`Unit`・`Scale`・`Sum`・`Tensor`・`Act` | 最外層に状態の空間、作用節点にも選択済みの空間を持つ |
| 複合演算子 | `Local`・`Identity`・`Scale`・`Sum`・`Product`・`Adjoint` | ambient の束縛は最外層だけにあり、子の演算子構文には保持しない |

`Local` は因子空間と**局所式全体**を持つ。たとえば局所の和を配置した式と、配置後に加算した式は別の構造として保持できる。

構築時にも限定的な構造処理がある。和の単一項はその項を返し、空の和は zero とする。演算子の列からの積は左結合の二項 `Product` を作り、空の積は identity になる。状態の空 tensor は `Unit`、単一入力は入力の構文になる。表示できるのはこれらの処理**後**の構造であり、元の Rust コードや除去済みの構築操作は復元できない。

### 2.3. 評価・順序・共有

- `scaled` は明示的な零・一の係数も保持する。項の重複や零係数を表示側で除去する根拠はない。
- `A * B` は右の `B` が先に作用する。`psi.act(&b).act(&a)` は `A(B psi)` を表す。積の因子は保存順で表示する。
- ordinary / graded の違いは空間にある。graded な式の評価時には parity・因子順序に応じた処理があるが、表示では並べ替え、符号の算出、parity string の挿入を行わない。
- 式と空間は `Arc` で不変な実体を共有する。表示は借用だけで行い、primitive・係数・Index を複製する必要はない。
- 深さ20,000の式・空間を小さいスレッドスタックで評価／破棄する既存テストがある。表示だけ関数再帰へ戻すと、既存の利用範囲に新しい stack overflow の原因を作る。

既存の [評価用走査](../../../crates/qmb-core/src/expr/traversal.rs)は係数の乗算・共役、和の分配、同一因子の集約などを含む。表示の走査としては流用せず、直接、保存された節点を読む。

参照: [算術構築](../../../crates/qmb-core/src/expr/arithmetic.rs)、[空間](../../../crates/qmb-core/src/space.rs)、[局所式のテスト](../../../crates/qmb-core/src/expr/tests.rs)、[複合式のテスト](../../../crates/qmb-core/src/expr/composite_tests.rs)、[空間のテスト](../../../crates/qmb-core/tests/spaces.rs)。

## 3. 数式風 `Display` の推奨書式

以下は**出力案**であり、現行の出力や実行確認済みの結果ではない。`A`・`B`・`C` は演算子式、`psi` は状態式を表す説明用ラベルとする。

### 3.1. 基本の表記

| 保持しているもの | 表示案 | 判断理由 |
| --- | --- | --- |
| 状態／演算子 primitive | primitive 自身の `Display` | 代数ごとの名称は各 primitive が担当する |
| 空の和 | `0` | 係数型から零を生成しない |
| 複合演算子の `Identity` | `I` | 係数型から一を生成しない |
| 空 tensor 上の状態 `Unit` | `unit` | 零状態や局所の ket `\|0>` と区別する |
| `Scale(c, E)` | `(c) * E` | 複素数・負数を含め、係数を常に括弧で区切る |
| `Sum(A, B, C)` | `A + B + C` | 保存順を維持する |
| `Product(A, B)` | `A * B` | 非可換な積とその順序を明示する |
| 状態の `Tensor(s, t)` | `s ⊗ t` | 演算子の積と区別する |
| `Act(psi, A)` | `act(A, psi)` | 積・tensor と区別し、左作用であることを明示する |
| `Adjoint(A)` | `(A)†` | 未評価の随伴を明示し、対象範囲を常に括弧で囲む |
| `Local(factor, E)` | `E[index]` | 因子の Index を付ける。複合的な局所式には括弧を付ける |

Unicode は `⊗` と `†` に限定し、primitive 名は既存の名称を基本とする。ASCII 専用モードや LaTeX は初回実装の対象から外す。Unicode 記号が UTF-8 のログに出力されることを使用例に記す。

複合演算子の `Local` 同士の積を、自動で tensor 記号へ置き換えない。同じ Index への積や graded な順序を含むため、保存している `Product` として表示する。

### 3.2. 括弧と結合

基本の優先順位は弱い順に、和、状態 tensor、積／係数倍、配置・primitive・関数形とする。随伴は必ず引数を括弧で囲んで後ろに `†` を付ける。

同順位でも構造を隠す場合は括弧を残す。初回実装では、次の保守的な規則を推奨する。

- 和の子が和なら括弧を付ける。n項の和と入れ子の和の違いを維持する。
- 二項積の左の積は左結合の表記に従って括弧を省略し、右の積には括弧を付ける。
- 係数倍の operand が和・積・係数倍・tensor のときは括弧を付ける。積の子が係数倍の場合も括弧を付け、係数倍の範囲を保つ。
- tensor の子が和または tensor のときは括弧を付ける。保存されている tensor の入れ子を勝手に平坦化しない。
- 配置する局所式が primitive 以外のときは、全体を括弧で囲んでから `[index]` を付ける。

| 構造・構築の違い | 表示案 |
| --- | --- |
| 和を左因子にした積 | `(A + B) * C` |
| 左結合／右結合の積 | `A * B * C` / `A * (B * C)` |
| 入れ子の和 | `A + (B + C)` / `(A + B) + C` |
| 和の係数倍 | `(2+3i) * (A + B)` |
| 係数倍の係数倍 | `(2) * ((3) * A)` |
| 係数倍を右因子にした積 | `A * ((2) * B)` |
| 積の随伴 | `(A * B)†` |
| 二重随伴 | `((A)†)†` |
| 作用の連鎖 | `act(A, act(B, psi))` |
| 局所の和を一括配置 | `(Sx + Sy)[a]` |
| 局所の積を一括配置 | `(Sx * Sy)[a]` |
| 配置した2式の和／積 | `Sx[a] + Sy[a]` / `Sx[a] * Sy[a]` |
| 状態の tensor | `\|up>[a] ⊗ \|down>[b]` |
| tensor の入れ子 | `(\|up>[a] ⊗ \|down>[b]) ⊗ \|up>[c]` |

意味を誤って伝えないことを括弧削減より優先する。構造の完全な確認には `Debug` を使い、`Display` の出力が式構造の一意な識別子になることは保証しない。

### 3.3. 係数・零・単位元

係数は `C::Display` の結果をそのまま括弧内へ出す。`Complex` の実部・虚部を core が分解したり、実数だけの係数を判定して `+0i` を省いたりしない。

- 係数文字列が `2+3i` なら `(2+3i) * A`、`-1+0i` なら `(-1+0i) * A` とする。
- 明示的な零・一の係数、零を含む積、重複項を残す。`(0) * A`・`(1) * A`・`0 * A`・`A + A` は表示側で変形しない。
- 減算専用の節点はない。負の係数を含む和は `A + (-1+0i) * B` のように表示する。`A - B` への変換に係数の比較・符号判定を追加しない。
- `Operator::scalar(c)` は保存している `Scale(Identity)` に対応して `(c) * I` とする。
- 局所 identity は通常の primitive 表示に委ねる。表示時に `O::identity()` を生成したり、他の primitive が identity と等価か調べたりしない。

この方針なら `C: Display` だけで済み、表示のために `Zero`・`One`・`PartialEq`・数値演算・`Clone` を要求しない。

### 3.4. builtin primitive のラベル

primitive の `Display` はそれぞれの代数 crate に追加し、既存の derive `Debug` は維持する。

| 型 | 推奨ラベル |
| --- | --- |
| `SpinHalfOperator` | `I, Sx, Sy, Sz, Sp, Sm`（variant 名のまま） |
| `SpinOneOperator` | `I, Sx, Sy, Sz, Sp, Sm, Dxy, Q0, Qxy, Qyz, Qzx, Q1p, Q1m, Q2p, Q2m` |
| `FermionOperator` | `I, a, a†, n, Mx, My, Mz`（順に `I, Annihilate, Create, Number, Mx, My, Mz`） |
| `SpinHalfState` | `Up` → `\|up>`、`Down` → `\|down>` |
| `SpinOneState` | `Plus` → `\|+1>`、`Zero` → `\|0>`、`Minus` → `\|-1>` |
| `FermionState` | `Empty` → `\|0>`、`Occupied` → `\|1>` |

`SpinOneState::Zero` と `FermionState::Empty` は零ベクトルではない。primitive の `|0>` と空の和の `0` を明確に分ける。

`Sx` などは現在の primitive の名称を表示するだけで、物理的な角運動量 `Jx` への変換や規格化の変更はしない。core は型名や variant 名に依存しない。

### 3.5. Index と空間情報

標準の Index は `I: Display` で表示し、文字列ラベルなら `Sx[a]`、`Id128` なら完全な UUID を用いる。標準表示では UUID の自動省略や連番化は行わない。UUID などを短く読みたい場合は、次節の空間に基づく番号表示を使う。任意の別名は別途 callback で指定する。

`Display` は式本体を表示し、状態の全空間や演算子の ambient を末尾へ付けない。そのため次の限界がある。

- 束縛前後の演算子や spectator の異なる束縛先は同じ数式風表示になり得る。
- ordinary / graded の違いは、式本体だけからは分からない。
- 異なる Index の `Display` が同じ文字列なら、見た目では区別できない。

これらは `Debug` または空間を併記する利用コードで確認する。表示のために未束縛演算子の空間を推定したり、束縛を必須にしたりしない。

任意の `Display` の文字列を構文解析して優先順位を推測することはできない。primitive の実装とカスタムラベルは、ひとつの原子として読める表記にする。演算記号を含むラベルは自分で括弧を付け、改行・区切り文字を含む Index にはエスケープ済みのラベルを与える。汎用の表示は人が読む用途とし、任意の文字列の安全な直列化や round-trip は保証しない。

### 3.6. テンソル因子の順序による番号表示（追加提案）

Index 自体は変更せず、**基準にする HilbertSpace の葉の順序**を `0, 1, 2, ...` に対応させる表示を用意する。これは基底状態の番号や Geometry の Site 番号ではなく、テンソル因子の位置である。

たとえば `H = H_a ⊗ H_b ⊗ H_c` を基準にすると、Index が UUID でも `a → 0, b → 1, c → 2` として表示できる。

| 式 | H を基準にした表示案 |
| --- | --- |
| a と c に作用する積 | `Sx[0] * Sz[2]` |
| b だけに作用する演算子 | `Sy[1]` |
| c、a の順に構築した積 | `Sz[2] * Sx[0]` |

式中の出現順や作用する因子だけで連番を振らず、spectator を含む全空間の順序を使う。部分式へ降りても番号を振り直さず、状態 tensor の各子と作用内の演算子・状態にも同じ対応を使う。表示のために式の因子順序を変更しない。

基準空間の候補は次のとおり。

- 複合状態は自身の `space` を使える。
- 束縛済み演算子は自身の `ambient` を使える。
- 未束縛演算子は全因子の順序が未定なので、呼び出し側から空間を明示してもらう。式の出現順で全空間を推測しない。

まずは基準空間から番号対応表を作り、複数の式から共有できる借用 adapter を用意する。自身の空間を使う省略形は必要に応じて加える。具体的な API スケッチは次節に示す。空間の明示は表示上の対応付けとして扱い、元の式を bind・評価・変更しない。既存の束縛と異なる空間を許す範囲は実装時に定め、許す場合も実際の束縛を変更したと誤解させない説明を付ける。

adapter の構築時に参照する全 Index が基準空間に存在することを確認し、存在しない場合は `ExpressionError::MissingIndex` を返す案とする。数値表示と生の Index 表示を途中で混在させず、`fmt` に入る前にエラーを伝える。局所式を配置した節点と複合作用を含む全体を調べ、零係数の部分式も検査対象にする。

位置の取得自体は `I: Eq` と既存の `HilbertSpace::indices().position(...)` だけで実現できる。ただし、各参照をその都度探す方法や `Vec<&I>` を線型探索する方法は、因子数と参照数の積に比例する。取得が繰り返される今回の用途では、次節の再利用可能な対応表を推奨する。

同じ Index でも基準空間の順序が変わると番号が変わる。複数の式を比較する場合は同じ基準空間を渡す。元の Index や実際の束縛を確認する用途は `Debug` が担当する。

### 3.7. 番号対応表の構築と再利用（取得回数を考慮した推奨案）

番号表示では、**基準空間ごとに対応表を一度作り、検証・表示・複数の式に再利用する**。番号を出力するたびに空間を走査する構成を避ける。

現行の `no_std + alloc` と依存構成では、`alloc::collections::BTreeMap<&I, usize>` を使う案を推奨する。

- `space.indices().enumerate()` から葉順の番号を値として登録する。map 内のキーのソート順はテンソル因子の順序に使わない。
- 対応表は基準空間と Index を借用し、Index の `Clone` は要求しない。
- 検索に必要な `I: Ord` は番号対応表の構築・利用時だけに要求する。`Id128` は既に `Ord` を実装している。式や空間の構築・評価の既存制約は変更しない。
- 基準空間も対応表に関連付け、違う空間の番号を誤って共有しないようにする。HilbertSpace 内部の可変キャッシュや大域キャッシュは導入しない。
- 同じ対応表を使う複数の表示 adapter は、その表を借用する。各 adapter が map を複製・再構築する必要はない。

因子数を N、空間の保存節点数を V、位置取得回数を M とすると、目安は次のとおり。式の走査と文字列出力の費用は別に加わる。

| 処理 | 計算量の目安 |
| --- | --- |
| 対応表の構築 | 時間 `O(V + N log(N + 1))`、表の追加メモリ `O(N)` |
| Index から位置の検索 | 1回 `O(log(N + 1))` |
| 構築後の M 回の位置取得 | `O(M log(N + 1))` |

以下は**未実装の API スケッチ**であり、名称は未確定である。

```rust,ignore
let positions = FactorPositions::new(&space);
let state_view = state.display_with_positions(&positions)?;
let operator_view = operator.display_with_positions(&positions)?;
println!("{state_view}");
println!("{operator_view}");
println!("{state_view}"); // 対応表と検証済み adapter を再利用する。
```

`display_in(&space)` のような簡便形を設ける場合は、その呼び出しごとに表を構築する入口として説明し、繰り返す取得・表示には対応表を明示的に再利用する入口を案内する。

`Eq` だけでは、一般の Index 値からの高速な逆引きを保証できない。`Eq` だけの型向けの線型探索版は必要になった時点で別途検討し、高速な番号表示の標準経路とは区別する。`HashMap` を採用する場合は `Eq + Hash`、no_std 対応の実装・hasher・依存関係を追加で検討する必要があるため、現段階では新しい依存を要しない BTreeMap を優先する。

## 4. `Debug` の推奨契約

`{:?}` はコンパクトな構造表示、`{:#?}` は同じ情報を複数行で表示する。内部 enum を公開せず、表示上の節点名・フィールドで構造を伝える。

- 最外層に `LocalState`・`LocalOperator`・`State`・`Operator` の種別を出す。
- 複合状態には `space`、複合演算子には `ambient: None / Some(...)` を出す。`Act` に保持している選択済み空間も出す。
- `Primitive`・`Scale`・`Sum`・`Product`・`Tensor`・`Act`・`Adjoint`・`Local`・`Identity`・`Unit` を区別する。空の和は `Sum([])` とし、数学的な零判定に置き換えない。
- `Local` の因子と局所式、`Product` の `lhs` / `rhs`、`Act` の `operator` / `state` を明示する。
- `HilbertSpace<I>` にも `I: Debug` の条件付き `Debug` を追加し、`Factor` / `Tensor`、保存している `TensorKind`、子の順序と grouping を表示する。unit や単一要素の tensor wrapper も構造として残す。
- primitive・係数・Index はそれぞれの `Debug` に委譲する。文字列 Index は引用符付きの表示になる。
- `Arc` のアドレスや参照数、`has_action`・`pending_action` などの内部メタデータ、`SumExpr` の inline 格納の違いは出さない。

構造表示のイメージは次のとおり。これは書式案であり、空白やフィールド配置の最終仕様ではない。

```text
Operator {
    ambient: None,
    expression: Local {
        factor: Factor("a"),
        expression: Sum([
            Primitive(Sx),
            Primitive(Sy),
        ]),
    },
}
```

式の意味に関わる構造は確認可能にしつつ、Debug 文字列自体を保存形式や永続的な互換性の契約にはしない。構築前の source や、以前の演算子ハンドルにしかなかった ambient は復元しない。

## 5. 型制約と表示用ラッパー

### 5.1. 標準実装に必要な条件

| 型 | `Display` 実装の条件 | `Debug` 実装の条件 |
| --- | --- | --- |
| `LocalState<S, O, C>` | `S, O, C: Display` | `S, O, C: Debug` |
| `LocalOperator<O, C>` | `O, C: Display` | `O, C: Debug` |
| `State<I, S, O, C>` | `I, S, O, C: Display` | `I, S, O, C: Debug` |
| `Operator<I, O, C>` | `I, O, C: Display` | `I, O, C: Debug` |
| `HilbertSpace<I>` | 初回は追加不要 | `I: Debug` |

状態型は遅延作用を含み得るため、状態だけを表示したい場合でも型として `O` の表示能力が必要になる。節点の実行時の種類に応じて trait 制約を外すことはできない。標準の `Display`・`Debug` には評価能力や `I: Eq` を追加しない。番号表示 adapter は標準表示と別の実装とし、`I: Display` の代わりに対応表のための `I: Ord` を要求する。

標準 `Display` に `Debug` への暗黙のフォールバックは設けない。`Display` がない外部 primitive でも、`Debug` があれば構造表示を使える。型自体の表示能力がない場合でも、後述のラッパーで専用の出力方法を渡せる設計にする。

`LinearCombination` と公開パーツの数式風表示は、初回の4式型の対象とは分ける。既存 `Debug` を維持し、必要が出たら同じ括弧規則を使う表示を追加する。

### 5.2. ラッパーの推奨範囲

最初の用途は第3.6・3.7節のテンソル因子位置による番号化と、番号対応表の再利用とする。これを任意ラベルの callback に先行して提供する。

追加段階では、UUID に `a`・`b` などの別名を与えられるようにする。案としては、次のように式を借用する adapter を用意する。**以下のメソッドは未実装の API スケッチ**である。

```rust,ignore
// 出力先は core::fmt::Write。返り値は core::fmt::Result。
let view = expr.display().with_index(|index: &Id128, out: &mut dyn core::fmt::Write| {
    // 呼び出し側が用意した対応表や比較規則で別名を出力する。
    write!(out, "{}", label_for(index))
});
println!("{view}");
```

adapter は式と callback を保持し、`Display` を実装する。Index の callback を指定した場合は `I: Display` を不要にし、他の葉の条件だけを要求する。同じ仕組みを状態 primitive・演算子 primitive・係数へ必要に応じて広げる。callback を別々に持てば、状態型と演算子型が同一でも別のラベルを設定できる。

空間や式へ名前を保存せず、Index の同一性を変えない。対応表の方式を core が強制せず、`Hash`・`Ord`・`Clone`・`Eq` を表示側から一律に要求しない。別々の出力を比較したい場合は、呼び出し側が同じ対応表を使う。

初回から汎用テンプレート言語、公開の式分解 trait、外部 serializer、幅に応じた数式の自動折り返しは導入しない。複数行表示はまず `{:#?}` で提供する。

### 5.3. format 引数

初回は `{}`・`{:?}`・`{:#?}` を明示的な利用対象とし、数式用の `Display` では `#` に別の意味を与えない。`{:.3}` を全係数への精度指定として扱うような独自の解釈は設けない。必要なら係数 callback 側で精度を指定する。

式全体の幅・alignment・precision を完全に扱うには、長さの測定やバッファリング、文字数と表示幅の扱いを別途決める必要がある。初回はこれらの指定に特別な動作を約束せず、葉へ外側の format 指定を一括伝播しない。精度による式の切り詰めも行わない。この制限は rustdoc に記す。

## 6. 実装方針

1. `qmb-core/src/expr/format.rs` などに式の表示処理を置き、4式型の条件付き trait 実装から呼ぶ。型の定義や評価器へ表示用の trait 制約を伝播させない。
2. 局所状態・局所演算子・複合状態・複合演算子を借用する作業項目と、区切り文字・括弧・改行などの出力項目を明示的なスタックで処理する。`Act`・`Local` をまたぐ遷移も同じ走査内で扱う。
3. 和・tensor・空間の子の列は iterator の継続項目で処理し、幅の広い節点の全子をスタックへ一括投入しない。走査スタックの補助メモリは基本的に深さに比例させる。番号表示では、これに再利用する番号対応表の `O(N)` メモリが加わる。
4. 空間の構造表示も反復的に処理する。`factor_index()`・`kind()`・`children()` により、非公開の空間節点を公開せずに実装できる。
5. `write!` などから出力先へ逐次書き込み、式全体の `String` を作らない。失敗した `fmt::Result` は直ちに返し、後続の葉や callback を呼ばない。
6. `Debug` builder に子の式を渡して通常の `Debug::fmt` を再帰呼び出しする実装は避ける。コンパクト／複数行の区切り・インデントは作業項目で管理する。
7. builtin primitive の `Display` は各 crate に追加する。core に builtin 代数への依存や外部の表示用 dependency を追加しない。

既存の `LinearTerms`・`OpTerms`、`evaluate`・`expand`・`coordinates`・`trace` は表示経路から呼ばない。係数の共役、積の逆順化、graded lowering も行わない。

共有した部分式は出現箇所ごとに表示する。DAG の共有を圧縮した `let` 表記やアドレスによる識別は初回対象外とする。このため、共有節点数が小さくても出力が大きくなる場合がある。計算量は共有節点の総数ではなく、表示上の出現回数と出力文字数に依存する。深い `{:#?}` はインデントだけでも出力が大きくなる。

自動の深さ制限・無言の省略は導入しない。必要になった場合に、明示的な省略表示を行うラッパーを別途検討する。

## 7. 比較した案

| 案 | 利点 | 懸念・判断 |
| --- | --- | --- |
| `Debug` だけを追加 | builtin primitive の既存 `Debug` を利用できる | 日常的な数式風表示を満たさない。構造表示として採用 |
| `Display` だけを追加 | `println!` ですぐ使える | 空間や配置の構造確認が不足する。`Debug` と組み合わせる |
| ラッパーだけを提供 | 出力方針を明示でき、後の拡張もしやすい | 毎回 adapter が必要。標準表示と併用する |
| 外部 crate に完全分離 | core の実装を増やさない | 非公開節点へアクセスできず、公開走査 API の設計が先に必要。今回は core に置く |
| 評価・基底展開後の式を表示 | 数学的には短くなる場合がある | 保持している式を確認できず、能力制約と計算量も変わる。表示では行わない |
| 符号・一・零を自動判定して整形 | 人が手書きする式に近い | 比較・数値能力が必要で、任意の係数に適用できない。初回は係数を忠実に出す |

## 8. 実装時の検証項目

| 観点 | 必要な確認 |
| --- | --- |
| 節点の網羅 | 4式型の全節点、局所／複合、零・identity・Unit を確認する |
| 括弧 | 和を含む積、右に入れ子の積、係数倍の積・入れ子、和・tensor の grouping、積・係数倍の随伴を期待文字列で確認する |
| 非可換性 | `A * B` と `B * A` の出力順、`act(A, act(B, psi))` の作用順が保たれる |
| 配置の範囲 | `(Sx + Sy)[a]` と `Sx[a] + Sy[a]`、局所の積・作用全体の配置を区別できる |
| 係数 | `Complex<f32>` / `Complex<f64>`、負数、純虚数、明示的な零・一、特殊値を評価・比較せず表示する |
| primitive | builtin の全 variant を確認し、特に ket `\|0>` と零ベクトルを区別する |
| 空間・束縛 | 未束縛演算子、空間付き zero / identity、spectator、ordinary / graded、nested / singleton / empty space が `Debug` で確認できる |
| 因子位置への番号化 | UUID や、`Ord` を持つが表示能力・`Clone` のない Index でも番号表示できる。葉順と map のキー順が異なる場合、spectator による欠番、部分式間での番号の共有、基準空間の並べ替え、範囲外参照の構築時エラーを確認する |
| 対応表の再利用 | 複数の式・同じ adapter の再表示で表を再構築せず、Index の複製も発生しない。対応表の利用に必要な `Ord` を、既存の構築・評価へ伝播させない |
| graded な順序 | 異なる因子の odd primitive を逆順に構築しても、表示でソート・符号付加・parity string 挿入が発生しない |
| 評価しないこと | 代数能力を実装しないが表示できる型で表示する。既存の呼び出しカウンタの方式も参考に、primitive 規則が呼ばれないことを確認する |
| 制約と所有権 | `Display` のみ／`Debug` のみ、非 `Clone` の葉で表示できる。表示能力を一切持たない型でも従来の構築ができる。ラッパー追加時は callback で該当の表示制約を外せる |
| 共有・深さ | 共有葉を残した深さ20,000の和・積・係数倍・作用・随伴と深い空間を小さいスタックでコンパクト表示する。受け皿は出力を保存しない writer にする |
| 複数行 | 適度な深さの `{:#?}` でインデントと順序を確認する。深いケースでは出力上限でエラーを返す writer も用い、巨大な空白列をテスト用 `String` に蓄積しない |
| 出力失敗 | 途中で `fmt::Error` を返す writer に対して即座に停止し、後続の葉を表示しない |

検証コマンドは実装内容に応じて絞り、core と builtin 3 crate の関連テスト・doc test、workspace の format・Clippy、および既存の feature 構成の確認を行う。`no_std + alloc` を維持し、ホストでの確認と専用 no_std target での実証は区別する。

## 9. 残る判断と今回の確認範囲

実装着手時には、本書の書式案（特に `act(...)`・Unicode・係数の一律括弧）と番号表示 adapter の契約を確定する。番号表示は初回に含めることを推奨し、任意ラベルの callback は追加段階とする。ラッパーの公開型名・正確な API はスケッチ段階である。

今回行ったのは現行ソース・既存テスト・設計文書の読解と、本書および v3 計画からのリンク追加である。Rust の実装は変更しておらず、提案した表示の実装・コンパイル・テストは行っていない。深さ20,000などの記述は既存テストの内容を確認したものであり、この調査でのテスト再実行結果ではない。
