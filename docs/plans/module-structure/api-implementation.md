# Public API implementation plan

## Objective and scope

Implement the reviewed public API and preludes in the [API assessment](api-assessment.md). The review is complete; verify its details during implementation. This is a plan, not authorization to change code. Breaking old paths is intentional. Preserve behavior, applicable trait and iterator guarantees, error semantics, feature gates, `no_std`, supported Rust versions, and public capabilities except for the explicitly agreed removals or visibility changes.

The target has public definitions at their agreed semantic module paths, with public re-exports only in each library crate's root `prelude`. Root definitions and semantic aliases remain where agreed. Remove the old core compatibility aliases, parent and root facades, the specified expression parts' public access, and export's third-party re-exports. Do not use another syntaqs crate's prelude within repository crates other than `examples`; this includes their tests, examples and doctests. Update consumers to canonical paths.

## Batch rules

Each numbered stage is a small unit of implementation and verification. Before starting a unit, inspect the worktree, affected definitions, imports, tests and destinations. Preserve unrelated work. Update affected workspace crates, examples, integration tests, doctests and the excluded BLAS fixture as needed for the unit. Test canonical paths from outside the defining crate, not solely through internal imports. Check changes to public signatures and reachable types; do not substitute a test count for behavior coverage. Record results and deviations here.

Core has many downstream consumers. To keep intermediate units buildable, retain an existing public re-export temporarily only when needed for not-yet-migrated callers, and record its removal in the relevant unit. Migrate callers to canonical paths, then remove temporary exports; no compatibility facade remains at completion. Do not retain two independent definitions of one public type. Each completed unit must compile with its affected consumers; avoid a workspace-wide broken intermediate state. If an agreed contract proves infeasible, record the evidence and revise it before proceeding rather than silently narrowing functionality.

## Execution stages

- [ ] **0. Baseline and migration map.** Inspect the worktree and current API/test targets, including `pub use`, signature types, associated types, iterator contracts, crate features, and consumers. Record the specific intentional removals, planned temporary exports and per-unit checks. Identify pre-existing failures before attributing regressions. Do not redo the API design; resolve omitted details while implementing.
- [ ] **1. Core expression parts.** Create the agreed independent `Term` and public `IntoTerms` without exposing internal `ScaleExpr` or `IntoOperands`; preserve construction, field access, ordering and iterator guarantees used by `LinearCombination` and `from_terms`. Remove public access to `SumExpr`, `ScaleExpr`, `ProductExpr`, `ActExpr`, `AdjointExpr` and `IntoOperands` when consumers are migrated. Replace tests of exposed implementation containers with tests at their proper internal ownership or tests of preserved public behavior, retaining coverage. Run core unit, integration and doctests, targeted no-default-features and downstream checks; check external construction and iteration.
- [ ] **2. Core canonical paths and prelude.** Expose `expression::local` and `expression::error`, move `ExpressionError`, `BasisError`, `Coordinates`, `dim_state` and `dim_op` to their agreed defining modules, and add the core prelude. Migrate all core and workspace consumers, documentation and fixture imports. Remove root/parent facades, `ops`, `expr`, the dimension re-exports and the empty compatibility error module once callers are migrated. Check core tests and doctests, affected downstream compilation and no-default-features; verify public paths, prelude usage, and rejection of removed compatibility paths.
- [ ] **3. Basic.** Move `Id128` and `Tag` to public `index`, add their prelude, and migrate callers and doctests. Verify basic tests and doctests, canonical and prelude imports, and affected consumers.
- [ ] **4. Geometry.** Implement the agreed `geometry`, `relation` and `mapping` paths; move `Boundary`, `SiteGroup` and `SiteGroupError` to their defining parents, expose the agreed children, add the prelude, and remove facades. Update physical models, other consumers, tests and docs. Verify geometry and affected model tests, custom geometry/relation implementations, errors, direct paths and prelude usage.
- [ ] **5. Normalize.** Expose `norm` and `expectation`, define `NormalizationError` at the root, retain private helpers, and add the four-trait prelude. Migrate callers and docs; verify normalize and affected shared tests, errors, doctests and public paths.
- [ ] **6. Export.** Define `Exported` and `ExportError` at root, expose agreed `matrix` and `vector` child modules, add the prelude and remove parent facades and `ndarray`/`sprs` re-exports. Migrate dependent manifests, code, tests and docs to compatible direct dependencies; preserve optional feature behavior. Test export and shared integration packages separately with no backend, `ndarray`, `sprs`, and both; verify metadata, error paths, direct dependency types and preludes.
- [ ] **7. Lie.** Define `FamilyExpression`, `LieError` and `lie_bracket` at root; expose agreed domain/child paths, add the prelude, and remove facades. Keep `FamilyExpression` sealed, numerical kernels and spectral internals private, and diagnostics reachable. Migrate consumers and docs; run Lie tests and doctests, shared Lie workflow, example and excluded BLAS fixture, and check paths, numerical error conversions and prelude imports.
- [ ] **8. Physical-system crates.** Migrate spin-half, spin-one and fermion root facades to canonical `basis`, `state`, `operator` and `models` paths and add each agreed four-item prelude. Update consumers, examples and doctests. Test each crate and affected cross-crate workflows, including the three preludes together and their coexistence with core's prelude.
- [ ] **9. Final review and validation.** Audit public paths against the assessment, including signature types, iterator and associated types, feature-gated exports, and negative checks for removed compatibility paths and non-prelude re-exports. Check the cross-crate prelude rule and common prelude combinations. Update affected README, rustdoc and permanent design documentation to the implemented API; remove stale old-path guidance. Review the final diff, test discovery and behavior coverage for unintended changes. Record results and limitations.

## Final verification

Run the repository CI checks appropriate to this workspace: workspace tests with default, all features, and no default features on MSRV 1.85.0 and stable; workspace all-features build and all-target no-default-features check; isolated export and shared-test backend combinations; Lie-only workflow and example; downstream BLAS fixture and provider-selection checks. Run workspace and fixture formatting, all-target all-features Clippy, and all-features rustdoc with warnings denied. Run focused checks at each stage instead of deferring all verification to the end. Report unavailable environments or pre-existing failures accurately.

## Completion criteria

All nine public library crates expose their agreed paths and preludes, with no obsolete compatibility or non-prelude public re-exports. Intended implementation parts are private; required public signature types and user-extensible contracts remain usable. Workspace consumers, fixtures, examples and documentation use the new API and follow the prelude rule. Relevant tests and repository checks pass, or limitations are explicitly recorded. Record completed stage results and any final differences from the assessment.
