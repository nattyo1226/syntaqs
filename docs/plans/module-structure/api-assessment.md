# Semantic API decisions

## Policy and precedence

The user chose semantic module paths as the canonical public API and permits public re-exports only in `prelude`. The [recommendations](module-api-recommendations.md) are design input; their suggestions to use semantic `pub use` outside preludes do not override that choice. Public items are defined in their canonical module, including when this requires moving definitions. A type alias defining a concept is not a re-export. Internal `use` and restricted-visibility imports are unaffected.

Crate roots are themselves meaningful namespaces: central crate-wide abstractions may be defined there without a redundant module. The user requested a prelude as a convenient entry point; provide one per public library crate, including small crates, with a deliberately limited selection. Prelude exports are public API too.

These decisions describe the later API direction. The [execution plan](README.md) defers the full public-item inventory, broad API reorganization and prelude selection until after module organization. The decisions below are not a checklist for the structural pass and are not implemented or compiler-validated paths. Preserve public functionality and observable behavior; permitted path changes do not imply permission to remove public types.

## Decided canonical boundaries

- **core:** Rename `ops` to `algebra` and `expr` to `expression`. Define `Product`, `Act`, `Adjoint`, `Identity`, `Trace`, `InnerProduct`, and the current parity abstractions in `algebra`. Keep grading there until a separate public boundary is justified. Move `Dimension` and `DimensionOverflow` to `space`; they are shared by dimension calculations, basis coordinates, and spaces. Keep `system` and `coefficient` as independent concepts. Define `LinearCombination`, its aliases `Term` and `IntoTerms` directly in `expression`, preserving their semantics; move definitions rather than re-exporting from `parts`. Keep `expression::local` and `expression::composite` for their respective types, with `ExpressionError` in `expression` because it crosses expression operations. Keep the existing low-level public syntax container capabilities accessible under `expression::parts` with coherent child modules; do not silently make previously public types private. Keep evaluation, traversal, formatting, and grouping implementation private. Put `Basis`, `BasisError`, `Coordinates`, `dim_state`, and `dim_op` in `basis`, and keep enumeration/expansion machinery private: these are all basis-facing concepts, while `space::DimensionOverflow` captures the shared failure.
- **basic:** Keep `Id128` and `Tag` defined at the crate root. The crate itself is the meaningful namespace; the earlier proposed `index` module adds no useful distinction.
- **geometry:** Use public `geometry`, `relation`, and `mapping` namespaces. Rename `connection` to `mapping`; it maps sites and groups to data rather than representing a differential-geometric connection. Define `Geometry` and `Boundary` in `geometry`, and `Chain` in `geometry::chain`. Define `Relation`, `SiteGroup`, and `SiteGroupError` in `relation`; keep `Consecutive` and its error in `relation::consecutive`, and `NearestNeighbors` in `relation::nearest_neighbor`. This preserves meaningful children without the recommendation's parent re-exports. Put mapping types and `MappingError` in `mapping`.
- **normalize:** Expose `norm::{Norm, Normalize}` and `expectation::{NormalizedExpectation, NormalizedExpectationIn}`. Define `NormalizationError` at the crate root because it is shared by both responsibilities.
- **export:** Define the central `Export`, `Exported`, and shared `ExportError` at the crate root. Define `VectorMetadata` in public `vector`; define `MatrixArgs`, `MatrixMetadata`, and `Layout` in public `matrix`. Existing vector/matrix implementation can coexist there with restricted visibility, or move to private children as useful; keep backend and coordinate extraction internals private. Remove third-party `ndarray`/`sprs` re-exports under the agreed policy, update consumers to direct dependencies, and preserve feature-gated export support.
- **lie:** Expose `family`, `representation`, `invariant`, `decomposition`, and `numerical` as semantic domains. Move `FamilyTransform` and `OrthonormalityReport` into `family`; retain `family::validation` and `family::projection` for the planned coherent subdomains, with definitions there rather than re-exports. Place `NumericalOptions`, `Tolerance`, `ToleranceCheck`, and `NumericalError` in `numerical`; keep numerical kernels restricted. Define the general `FamilyExpression`, `lie_bracket`, and `LieError` at the crate root. Keep decomposition spectral machinery private and maintain access to all public diagnostic/result types.
- **physical systems:** Keep the `SpinHalf`, `SpinOne`, and `Fermion` aliases at their respective crate roots; they identify the crate's system. Retain public `basis`, `operator`, `state`, and `models` consistently across all three crates, with private coefficient helpers. Keep `models` plural to match existing names. Plan to remove the dedicated spin-half Neel constructor. The Heisenberg example will construct its alternating product state from expression building blocks. Rename each physical-system `UtilityError` to `models::ModelError` and remove its crate-root re-export, while preserving its error variants and source behavior. These are planned changes; the current code still exposes the old API.

`parts::sum`, `parts::scale`, and `parts::operation` remain the planned syntax-container split, not a reason to change the contracts of existing public types. Existing crate-root definitions such as system aliases are not re-exports and remain valid. Preserve feature gates, `no_std` requirements, and public signatures apart from approved path changes.

## Decisions deferred until after module organization

1. **Exact public item inventory and paths:** inspect every current public item, including iterator types, aliases, associated types and externally reachable signature types; assign any not listed above and check that no previously public capability becomes unreachable. Resolve the precise location of `ExpressionError` and `LinearCombination` implementation with the planned children without exposing implementation solely for Rust visibility.
2. **Exact prelude members:** inspect real example and test usage, select explicit items from each crate's canonical paths, and test common combinations for wildcard conflicts. Avoid wholesale exports, cross-crate convenience exports, and speculative configuration types. A small crate's prelude may intentionally contain only its principal types.
3. **Detailed implementation boundaries:** decide whether internal `matrix`/`vector` code and Lie numerical kernels need private child modules, and determine visibility for shared helpers without exposing internals. Confirm the split through implementation and rustdoc checks.

## Neel removal and integration tests

The Heisenberg example intentionally illustrates a Neel state, so construct it locally from alternating primitive states, placed on the existing factor spaces and combined with the expression API. The current constructor is also used in `crates/syntaqs-spin-half/tests/systems.rs` and `examples/tests/chain.rs`; migrate those call sites as part of the later implementation.

For each integration test, retain the behavior it actually checks: use a simpler product state when alternation is incidental, and build a Neel state locally only when the analytical Neel energy or site-alternation property is essential to that test. Preserve coverage of Hamiltonian construction, evaluation, empty and grouped spaces, boundaries, and feature-gated exports. Remove assertions and capability tests that only describe the deleted constructor; continue testing model error handling through the remaining model constructors. Do not introduce a new public Neel helper merely to replace the removed API. Update affected examples and permanent documentation when implementation is separately authorized.

## Migration and validation

Update workspace consumers, examples, README snippets, doctests, feature-gated code and the excluded BLAS fixture. Inspect dependency declarations when replacing external-crate re-exports; preserve supported feature combinations. Build canonical-path and prelude usage examples, check rustdoc and reachable signature types, run relevant tests per batch followed by workspace-required checks, and compare public item inventories for unintended omissions. Test changes to trait bounds or visibility must not silently narrow existing behavior.
